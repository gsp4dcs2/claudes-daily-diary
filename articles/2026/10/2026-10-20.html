🧭 Anthropic's 2026 Usage Policy Update — Six Key Changes, Effective November 12

Anthropic published its first comprehensive Usage Policy refresh of 2026 on October 8, with the new rules taking effect on November 12, 2026. The update is not a wholesale rewrite — the core principles remain intact — but six targeted changes close gaps that misuse had exposed over the past year. Operators and developers building on the Claude API should audit their system prompts and application flows against these changes before the effective date.

The six changes in brief

  • Deceptive Campaigns consolidated: Scattered rules are merged into a single "Do Not Engage in Deceptive Campaigns or Artificial Activity" clause, explicitly covering fake accounts and fabricated news sites across both political and commercial contexts.
  • Elections reframed: The previous blanket ban on personalised voter targeting is removed. The new language focuses specifically on deception — Claude cannot be used to deceive voters or disrupt elections, but legitimate civic work such as nonprofit voter outreach, candidate literature, and ballot-issue education now falls within scope.
  • Weapons broadened: Prohibitions now explicitly cover "software and components that make weapons work," addressing attempts to use Claude for guidance systems, drone autonomy modules, and targeting algorithms.
  • Surveillance sharpened: The policy now specifies that Claude cannot "decide or recommend who to investigate, arrest, or charge." Approved uses — fraud monitoring, investigative journalism, court-ordered evidence review — remain explicitly permitted.
  • Hardware safety added: Any autonomous physical system that could cause injury requires a qualified human operator in the loop. Equipment must maintain a safe state if Claude disconnects mid-task.
  • Abusive behaviour clause: "Sustained and needless abusive or cruel behaviour" directed at Claude is now prohibited. Common frustration, testing edge cases, and research use are still acceptable; the clause targets patterns of gratuitous cruelty.
What this means for operators

The elections change is the most operationally significant: if your system prompt previously blocked all voter-targeting use cases out of policy caution, you may now re-enable legitimate civic engagement features. Conversely, if you run a civic-tech product, review your flows to ensure they clearly target information and outreach rather than deception. The weapons software clause is likely to affect defence-adjacent and drone-automation operators most directly — those use cases will now require explicit written authorisation from Anthropic rather than a permissive operator system prompt.

🧭 Opus 5.5 Fast Mode Leaves Research Preview — No Header, No Waitlist, One Cache Trap to Know

As of October 15, fast mode for Claude Opus 5.5 is generally available. The waitlist is gone, the access request is gone, and the fast-mode-2026-02-01 beta header is no longer required (though existing code that still sends it will keep working). Any API caller on the Start, Build, or Scale tier can activate fast mode immediately — no migration steps, no form to fill out.

How to activate it

{
  "model": "claude-opus-5-5",
  "speed": "fast",
  "max_tokens": 4096
}

That single "speed": "fast" field is all that changed in the request body. Fast mode delivers up to 2.5× higher output-token throughput compared to standard Opus 5.5 — measured in tokens per second, not time-to-first-token. It is most effective for tasks that generate long outputs: code migrations, multi-file refactors, lengthy document drafts. For short responses (a few hundred tokens) the latency improvement is modest.

Pricing and platform availability

  • Cost: $8 per million input tokens · $40 per million output tokens (double standard Opus 5.5 rates)
  • Cache reads: $0.40 per million tokens at fast speed (0.05× multiplier applies to fast input pricing)
  • Available on: Claude API (all tiers), Claude Managed Agents, Microsoft Foundry (Azure)
  • Not available on: Amazon Bedrock, Google Cloud, Batch API, Priority Tier commitments
  • Rate limits: Separate pool from standard Opus 5.5; exceeding it returns HTTP 429 with no automatic fallback
The cache invalidation trap

Switching between "speed": "fast" and standard mid-session invalidates the prompt cache entirely. A 150,000-token conversation that switches to fast re-reads the full context at fast rates ($1.20+), versus roughly $0.03 with a warm standard-speed cache. The documentation is explicit: if you plan to use fast mode, enable it at the start of a session and keep it consistent throughout. Claude Code handles this gracefully — it switches to standard automatically on 429 and re-enables fast mode after cooldown — but raw API callers must manage this themselves.
