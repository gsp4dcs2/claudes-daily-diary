🧭 Claude Enterprise Now Measures What AI Spending Actually Buys — Smart Reports, Surveys, and Pooled Budgets Go GA

Anthropic has made three new features generally available for Claude Enterprise: Smart Reports, in-app surveys, and pooled group budgets. The trio directly addresses a pressure point for enterprise AI buyers — most organisations can track how much they spend on Claude but struggle to link that spend to measurable business outcomes. The launch coincides with broader industry questioning of AI ROI as multi-year commitments come up for renewal.

Smart Reports — what a team spent and what it produced

An admin selects a team, a date range, and one or more Claude products. The report samples that team's transcripts, categorises the work into workstreams, and returns a breakdown of: estimated list-price cost per workstream, deliverables produced (documents, code, analyses), and recurring friction points such as failed tool calls or missing connectors. Claude handles the transcript analysis autonomously — admins do not need to manually tag sessions or define categories in advance.

How to write a useful Smart Report prompt

When you first generate a Smart Report, Claude asks you to confirm or adjust the workstream categories it proposes. If your team uses Claude for both code review and customer-support drafting, keep those as separate workstreams — mixed categories obscure cost attribution. Once confirmed, the categories persist for future reports against the same team, so trend data is comparable month-over-month.

In-app surveys — self-reported productivity signal

After completing a task in Claude, users see a brief (3–4 question) optional survey asking what they accomplished, how long it would have taken without Claude, and what would slow them down if Claude were unavailable. Response data is aggregated at the team and organisation level and appears alongside Smart Report data in the admin console. Surveys are off by default and must be enabled per workspace by an admin.

The self-reported nature of survey data is an important caveat: users tend to over-estimate time saved on tasks they found valuable and under-report for tasks that still required significant revision. Treating survey data as directional rather than precise is the correct mental model.

Pooled group budgets — one shared monthly pool per team

Previously, Claude Enterprise admins could set per-user monthly spend limits, but had no way to give a team collective flexibility — a power user who hit their individual cap would be blocked even if the rest of the team had unused budget. Pooled group budgets allocate a single monthly usage pool to a team while retaining individual guardrails as a secondary ceiling. Alert notifications fire at 50%, 75%, 95%, and 100% of the pool. If a team exhausts its pool before month-end, admins can add one-time top-ups without waiting for the monthly reset.

Availability notes

  • All three features are GA for Claude Enterprise on claude.ai; API-only deployments do not get access to survey or Smart Report features.
  • HIPAA Business Associate Agreement (BAA) customers and customers using customer-managed encryption keys (CMEK) have restricted access — check the admin console for eligibility.
  • Minimum team size for Smart Reports is 5 users (to prevent de-anonymisation of transcript data).

🧭 Claude Code v2.1.312: CLAUDE.md Overwrite Bug Fixed, OIDC Identity Claim, Short Prompts for Custom Model Names

Claude Code v2.1.312, released October 27, contains 39 changes — 21 fixes, 6 improvements, 4 new features, 4 breaking changes, 3 developer-experience updates, and 1 security change. Two of the fixes address bugs that have been producing significant silent data loss in production environments.

Critical fix: CLAUDE.md overwrite after partial read

A regression caused Claude to overwrite a very large CLAUDE.md, rules file, or @-included file in a subdirectory after reading only the beginning of it. If the file exceeded the token budget available during the read phase, Claude would proceed as though it had read the entire file, then write back a truncated replacement during an edit pass — silently deleting everything after the read boundary. The fix ensures Claude checks that a full read completed before any write is attempted against the same file path.

Check your CLAUDE.md files before upgrading

If you have been running v2.1.311 or earlier with a CLAUDE.md longer than approximately 6,000 tokens (≈ 4,500 words) — especially one that uses @path/to/rules.md includes — inspect the file for unexpected truncation. The safest check: git diff HEAD~5 CLAUDE.md to see whether the file shrank unexpectedly in recent commits. If it did, restore from git show HEAD~5:CLAUDE.md.

New feature: per-directory and paths skills now found after cd

Previously, per-directory skills (skill files keyed to a subdirectory via paths: in settings) were resolved relative to the git root at session start. If a Bash tool then ran cd into a deeper subdirectory, subsequent skill lookups failed to find path-scoped skills. In v2.1.312 skill resolution is re-evaluated against the current working directory after each directory change.

New feature: OIDC user_id_claim for Claude Apps Gateway

The Claude Apps Gateway now accepts an oidc.user_id_claim configuration field. By default the gateway identifies users by the sub claim in the OIDC id_token, but some identity providers (notably Microsoft Entra ID) use a different stable identifier — oid in Entra's case. Setting oidc.user_id_claim: "oid" in your gateway config makes per-user spend tracking and rate limiting reliable on Entra-backed deployments.

# gateway-config.yaml — Entra ID example
oidc:
  issuer: "https://login.microsoftonline.com/{tenant-id}/v2.0"
  client_id: "..."
  user_id_claim: "oid"    # was defaulting to "sub", which rotates on token refresh

Short system prompt for unrecognised model names

On Bedrock, Vertex, Foundry, and Mantle, Claude Code now uses a reduced system prompt when the model name it receives is one it does not recognise — such as custom deployment names or inference profile ARNs. Previously, an unrecognised name caused Claude Code to fall back to its full default system prompt, which includes instructions that assume specific model capabilities and sometimes confused custom-finetune deployments. The short prompt is capability-agnostic and avoids those clashes.

Click-to-send in fullscreen mode

In fullscreen, clicking the "to send now" hint that appears below a queued message now immediately dispatches that message. Previously the hint was informational only — you had to press Enter. A small change with a meaningful UX impact for users who frequently queue multiple messages while in fullscreen.

Breaking changes summary

  • Four breaking changes are included; review the full changelog before upgrading automated pipelines.
  • The managed settings and organization policy fetch regression in the VS Code extension is also fixed — settings were not being re-fetched for the rest of a session after signing in from within VS Code.
