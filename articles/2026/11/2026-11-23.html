🧭 Dario Amodei Publishes Post-IPO Open Letter: "Safety at Scale" — LBBT Governance Commitments Reaffirmed as a Public Company

On Sunday morning, Anthropic CEO Dario Amodei published a 3,000-word open letter titled "Safety at Scale" addressed to Anthropic employees, shareholders, and the broader AI research community. The letter, posted simultaneously to anthropic.com and distributed via the new Investor Relations portal at ir.anthropic.com, explains how Anthropic's safety commitments remain structurally protected now that the company is publicly traded. The core argument: the Long-Term Benefit Trust (LBBT) was designed precisely for this moment — public markets introduce short-term earnings pressure, but the LBBT's governance powers over board composition and extraordinary transactions mean that no hostile shareholder campaign can override the safety mission.

Key commitments in the letter

  • Safety research ring-fence confirmed: The LBBT voted unanimously prior to the IPO close to protect a minimum annual safety research allocation. The allocation is disclosed in percentage terms in Anthropic's annual report (now required as a public company) but not as an absolute dollar figure, to avoid creating a "safety budget" that could be reduced to the floor in bad years.
  • No "safety theatre" threshold: Amodei explicitly commits that if Anthropic's internal Responsible Scaling Policy (RSP) ever triggers an ASL-5 threshold — requiring a pause on new capability development — that pause will happen regardless of its impact on quarterly earnings. This is the most concrete statement Anthropic has ever made about how public market incentives interact with safety obligations.
  • METR autonomy evaluation cadence: Starting Q1 2027, Anthropic will publish quarterly summaries of METR evaluations (the third-party capability assessments used to set RSP thresholds). These will be filed as exhibits to the 10-Q. This is the first time an AI lab has committed to disclosing safety evaluation results on a public-company reporting schedule.
  • Interpretability investment: Anthropic will increase its interpretability research headcount by 40% in 2027, funded directly from the IPO proceeds. Amodei describes interpretability as "the best hedge we have against alignment failure at scale."

The governance backstop: how the LBBT actually works

The letter includes the clearest public explanation yet of the LBBT's mechanics. The Trust holds a golden share giving it veto power over: (1) any CEO succession that would remove the safety-first mandate from the job description; (2) any amendment to Anthropic's Certificate of Incorporation that would remove the Public Benefit Corporation clause; (3) any transaction that would result in a single external party controlling more than 30% of voting power. The seven LBBT trustees are appointed for staggered six-year terms and must include at least three members with AI safety research expertise. Amodei notes that this structure "was not an accident — it was the reason we chose to go public rather than remain private indefinitely."

What the METR disclosures mean for developers building on Claude

The commitment to quarterly METR evaluation summaries in 10-Q filings is unprecedented. For developers building production systems on Claude, this creates a predictable signal: if Anthropic ever discloses an RSP threshold proximity event (i.e., the model is approaching ASL-5 capability territory), that is a heads-up that compute allocation and API capacity decisions may change. Build your SLAs with that in mind. The Q1 2027 summary will be filed alongside Anthropic's first earnings release on February 12 — a date worth having in your calendar if you're a heavy API consumer.

🧭 MCP Registry 1.0 Launches at registry.anthropic.com — 312 Certified Servers Indexed on Day One

Anthropic launched MCP Registry 1.0 on Sunday, opening a fully searchable, indexed directory of Model Context Protocol servers at registry.anthropic.com. The registry replaces the previous informal GitHub-based community list and introduces a structured certification process, versioned metadata, and a one-click installation flow for Claude Code and the Claude desktop apps. At launch, 312 MCP servers were listed — 42 from Anthropic (marked Official), 87 from enterprise partners (Atlassian, Salesforce, GitHub, Linear, Notion, Figma, and twelve others), and 183 community-submitted servers that cleared the automated safety scan.

How the registry works

  • Certification tiers:
    • Official (Anthropic-built) — full audit, SLA guarantee, priority support.
    • Partner Certified — submitted by an enterprise partner, automated + manual security review, partner SLA applies.
    • Community Verified — open submissions; passes automated static analysis (tool schema validation, no shell injection patterns, no network calls to undeclared hosts) and a 72-hour public review period.
    • Provisional — pending review; can be installed manually but not via one-click.
  • Metadata schema: Each listing includes: tool manifest (all tool names and input schemas), declared network permissions, required environment variables, compatibility matrix (Claude Code version, OS), and an average latency benchmark run against claude-sonnet-4-6.
  • One-click install in Claude Code: From the registry listing, clicking "Add to Claude Code" opens a confirmation dialog in the IDE showing the tool manifest and permissions before installation. No manual settings.json editing required.
  • CLI install: claude mcp add registry:<server-slug> — this resolves the latest certified version and writes the config block.

Submitting your own MCP server

Community submissions go through a four-step process: (1) publish to npm or PyPI with an mcp.json manifest at the package root; (2) submit via the registry portal at registry.anthropic.com/submit; (3) automated static analysis runs within minutes; (4) a 72-hour public comment window for community review. The expected processing time from submission to Community Verified status is 3–5 business days once the comment window closes.

# Install an MCP server from the registry via Claude Code CLI
claude mcp add registry:linear-issues

# Install a specific version
claude mcp add registry:linear-issues@2.1.0

# View the tool manifest before installing
claude mcp inspect registry:linear-issues

# List all installed MCP servers and their registry status
claude mcp list --show-registry-status
Use claude mcp inspect before installing any server — including Official ones

The inspect command prints the full tool manifest: every tool name, its input schema, and its declared network permissions. This takes 10 seconds and tells you exactly what permissions you are granting. Even Official servers may declare network permissions broader than your project needs — for air-gapped or compliance-sensitive environments, review the manifest and restrict allowedHosts in settings.json after installation if needed.

🧭 Claude Code 2.1.331 Hotfix — Easel SVG Export Fixed, Enterprise Sign-In Loop Resolved

Anthropic pushed Claude Code 2.1.331 on Saturday evening, a targeted hotfix for two regressions introduced in Friday's 2.1.330 release. The update is auto-applied on next launch for all Pro, Max, Team, and Enterprise plan users; self-hosted runner operators should pull the updated image tag anthropic/claude-code-runner:2.1.331.

What was fixed

  • Easel SVG export corruption on large datasets (≥ 500 data points): When a chart was generated from a dataset with 500 or more rows, the SVG export would silently truncate the <path> element mid-string, producing a malformed file that failed to open in Inkscape, Figma, or browsers. The root cause was an off-by-one in the SVG path builder's buffer-flush logic. The fix ensures the path is always finalised with a proper Z close command before the buffer flushes. PNG export at all dataset sizes was unaffected.
  • Enterprise sign-in redirect loop for accounts with custom IdP: Users whose organisations had configured a custom SAML 2.0 identity provider (IdP) in the Admin Console experienced an infinite redirect loop on first sign-in after the 2.1.330 update. This was caused by the new enterprise auth flow failing to pass the relay_state parameter through the SAML assertion consumer, causing the IdP to restart the flow on each return. Fixed by preserving relay_state across redirects. Organisations using Anthropic's default Google or Microsoft SSO were not affected.
Affected by the SVG export bug? Check your files

If you used Easel to export SVG files between Friday evening (2.1.330 release) and Saturday evening (2.1.331 release), verify those files are intact by opening them in a text editor and checking that the final <path> element ends with Z"/> rather than being cut off mid-attribute. Corrupted files will need to be regenerated — re-run the original Easel command in 2.1.331 and the output will be correct. PNG exports from the same period are safe.
