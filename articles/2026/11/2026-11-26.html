🧭 How Claude Agents Migrated Anthropic's Own Messages API from Python to Rust — The Verification Problem Was Harder Than the Code

Anthropic today published a detailed case study on the migration of its production Messages API from Python to Rust — the same API that every developer call to Claude flows through. The headline numbers are striking: 70% reduction in CPU per request, 80% reduction in memory per request, and ~20% improvement in median time-to-first-token, all achieved without taking the service offline or pausing feature development. But the engineers leading the project — including Katelyn Lesse, whose post-publication thread on X has already circulated widely — say the performance wins were almost secondary. The genuinely hard problem was verification: how do you confirm that a nondeterministic AI service produces semantically identical outputs after a full language rewrite?

The three-loop verification architecture

The team built a three-tier verification system around a core insight: turn the production API itself into the verifier. Rather than relying on a test suite (which turned out to be dangerously coupled to the Python implementation), they ran shadow traffic against both versions simultaneously, comparing outputs at multiple checkpoints — validation, prompt building, tokenisation, and safety screening.

  • Inner loop (sandbox, <1 second feedback): Claude agents tested hypotheses locally using input/output fixtures, with no live model calls, to rapidly iterate on suspected fixes.
  • Outer loop (production, hours/days): Fixes that passed the inner loop were validated against shadowed live traffic before being merged. The team fingerprinted the shape of each difference — where it occurred in the pipeline and how large it was — without reading actual user content, preserving privacy throughout.
  • Memory loop (ongoing): Every time a human engineer overruled an agent fix or caught a repeated mistake, the correction was captured as a reusable rule. This compounding memory reduced recurring errors significantly by mid-project.

From 24% to 99.6% matching rate

When shadow testing began in April 2026, only 24% of Rust outputs matched their Python equivalents. By September, when public traffic switched over, the matching rate was 99.6% — close enough to production tolerance given Claude's inherent nondeterminism. The team notes that the incremental rewrite path (Rust for token reception and parsing only, Python for the rest) was tried first but abandoned: the cross-language overhead erased 60–70% of the CPU gains, making a full rewrite the only viable approach.

"Verification is the new bottleneck" — the lesson every AI-assisted migration team needs to hear

By August 2026, Claude agents were merging more than 1,000 changes per two-week period. Code generation had effectively ceased to be the rate limiter. What slowed the project down was the loop from "agent writes a fix" to "we have high confidence this fix is correct at production scale." Teams planning similar AI-assisted rewrites should invest early in automated, privacy-safe shadow-traffic infrastructure — not just test coverage — because tests that pass locally can fail at scale in ways that are invisible until you have live data to compare. The Anthropic team found more than 100 cases where test assertions had been silently weakened during the port, all of which were invisible to the standard CI pipeline.

🧭 Claude Duet Research Preview Opens in India — First International Market, with Waitlist Access Across All Paid Plans

Claude Duet — Anthropic's proactive background agent that monitors connected apps and executes tasks without being explicitly prompted each time — has opened its research preview in India, making it the first country outside the US to gain access. The US research preview launched on 23 October; India follows roughly five weeks later. Access is tiered: Pro, Max, and Ultra subscribers can join a waitlist, Team plan customers enter a public beta immediately, and enterprise accounts enter a managed private beta with Anthropic's customer success team. The standalone app is live on iOS, Android, and claude.ai.

Why India first, and what Duet does there

  • Usage context: India ranks second globally behind the US in Claude consumer usage, according to Anthropic's Economic Index. Indian professionals use Claude disproportionately for technical and programming tasks — a natural fit for Duet's proactive scheduling and workflow automation capabilities.
  • Language coverage: Duet inherits Claude Opus 5.5's support for all 35 languages on the platform, with particular attention to ten Indic languages: Hindi, Bengali, Marathi, Telugu, Tamil, Gujarati, Kannada, Malayalam, Bhojpuri, and Urdu. Anthropic says Indic-language performance has been an active investment through 2026.
  • Target users: The initial India focus is founders, operators, consultants, and small-business owners — segments where proactive task handling (meeting scheduling, financial forecast drafts, customer outreach queues) translates directly to time saved without requiring a dedicated operations team.
  • Bengaluru office: Anthropic's Bengaluru office, its second Asia-Pacific location after Tokyo, is now open. The India expansion and office opening are timed together as part of a broader commitment Dario Amodei confirmed in meetings with government and enterprise partners this week.
How to get early access as an Indian Team plan user

Team plan subscribers in India do not need to join a waitlist — the public beta is available directly at claude.ai/duet after logging in. Connect at least one integration (calendar, email, or task tool) during onboarding; Duet operates on context from connected apps and will surface fewer proactive suggestions without an integration. Pro, Max, and Ultra individual users should join the waitlist at the same URL; Anthropic says India waitlist priority will be weighted toward users who have active Projects and high weekly session counts, as these correlate with Duet delivering immediate value.

🧭 Claude Code 2.1.332 — MCP Server Skills in Beta, /fork and /workflows Commands, 93 Bug Fixes

Claude Code 2.1.332 shipped today with a feature that significantly extends what MCP servers can do inside a session: MCP server skills, now in beta. Any MCP server that exposes a skill manifest can surface those skills directly in the / menu as server:skill — the same menu where built-in slash commands live. This means developers can ship repeatable, composable workflows as first-class Claude Code commands without forking the CLI or writing a custom agent harness.

MCP server skills: what they are and how to expose one

A skill is a named, described callable that an MCP server advertises in its manifest. When Claude Code connects to an MCP server, it queries for the skill list and surfaces them under the server's namespace. Invoking /myserver:lint-and-fix, for example, runs the server-side skill with full access to the session context — current files, project root, and conversation history — without the user having to pass arguments manually.

# Minimal skill manifest (add to your MCP server's config):
{
  "skills": [
    {
      "name": "lint-and-fix",
      "description": "Run ESLint on changed files and auto-fix safe rules",
      "inputSchema": {
        "type": "object",
        "properties": {
          "staged_only": { "type": "boolean", "default": true }
        }
      }
    }
  ]
}

Other notable additions in 2.1.332

  • /fork (VS Code): Creates a branch of the current conversation from the last Claude reply. Useful when you want to explore two different approaches to the same problem without losing either thread.
  • /workflows (VS Code): Opens the agent map panel showing all currently running workflows and their status — a visual overview of parallel agent tasks without switching to the terminal.
  • PreSkillShellCommand hook: A new hook event that fires before any skill or slash command executes a shell subprocess. Use it to validate or veto shell invocations inline — for example, blocking rm -rf patterns before they reach the shell.
  • Computer use on macOS (updated safety rules): macOS computer-use mode now refuses a broader set of system-level actions (kernel extension installs, accessibility permission requests) and types at a reduced speed to give users time to interrupt. Existing automations that relied on fast typing or broad system access may need adjusting.
  • Auto mode on third-party providers: Sessions on AWS Bedrock Mantle, Google Cloud Agent Platform, and Microsoft Foundry now start in auto mode by default. The sonnet and opus model aliases on those providers now resolve to the 5.5 versions.
  • 93 bug fixes: Covering MCP plugin compatibility regressions, voice dictation stability, session compaction edge cases, and a long-standing freeze that could occur immediately after compacting a very long conversation.
Build a team-shared MCP skill library to standardise your most-repeated Claude Code workflows

MCP server skills are the first mechanism that lets a team ship and version their Claude Code automation separately from the CLI itself. Consider creating an internal MCP server in your monorepo that exposes skills for your most-repeated workflows: running your specific linter/formatter combination, generating a PR description from staged changes, running integration tests against a named environment, or scaffolding a new service from your internal template. These skills will appear consistently across every team member's Claude Code session once they add the server to their config — no copy-pasted slash-command scripts, no per-user CLAUDE.md hacks. The PreSkillShellCommand hook gives your security team a single interception point to audit or block shell calls originating from any skill.
